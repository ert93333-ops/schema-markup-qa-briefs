Schema markup QA checklist

Review JSON-LD before publishing pages or templates.

Use this checklist to catch syntax errors, required-field gaps, stale Product offers, duplicate entities, visible-content mismatch, and rich-result test blockers.

pre-publish schema review

Checklist focus

Valid JSON is only the first gate.

Compare fields, visible copy, URL access, and final official tests before a template goes live.

1. Confirm JSON-LD parses cleanly

  1. Remove comments from JSON-LD before publishing.
  2. Check that each script block parses as valid JSON.
  3. Verify every entity includes `@context` and `@type`.

2. Check the intended type

  1. For Product, verify `name` and at least one of `offers`, `review`, or `aggregateRating`.
  2. For Product offers, verify `price`, `priceCurrency`, `availability`, and URL fields.
  3. For Article, verify `headline`, `author`, and `datePublished`.
  4. For Organization, verify `name`, `url`, logo, and sameAs where useful.

3. Compare markup to visible page content

  1. Product names should match the visible product title.
  2. Prices, availability, and offer URLs should match the current rendered page.
  3. Descriptions should describe the visible page, not an older template or different SKU.

4. Look for duplicate or stale entities

  1. Multiple JSON-LD blocks can be valid, but template duplication should be intentional.
  2. Check repeated Product, Organization, or Breadcrumb entities for stale names and URLs.
  3. Retest after CMS, theme, pricing, or frontend changes.

5. Run final official tests

  1. Use Google's Rich Results Test for final code or URL validation.
  2. Confirm the page is accessible, not blocked by robots.txt, noindex, login, or staging rules.
  3. Remember that structured data can make pages eligible for rich results, but it does not guarantee appearance.
